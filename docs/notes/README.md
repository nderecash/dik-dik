# Working notes

These are not documentation. They are the notes the project was actually built from, kept in
the repository on purpose.

They read differently from everything in `docs/`. They are written in the second person, they
address the author directly, they contain half-finished thoughts, task lists, questions that
were later answered elsewhere, and decisions that were subsequently reversed. Some of them
have been overtaken by the code.

They are here because the reasoning is more useful than a tidied summary of it would be, and
because a project that argues for showing your work should show it.

## What is in here

| File | What it is |
|---|---|
| `early-design-notes.md` | The first pass at what the game was for, before any of it existed |
| `day3-checklist.md` | The gate the speech pipeline had to pass before the project was worth continuing. It passed on day one instead of day three |
| `playtest-checklist.md` | The checklist a full playthrough was run against, with the results that produced most of the bug fixes in the log |
| `OPEN-ISSUES.md` | The live list of known problems, decisions taken without consultation, and things needing a human. Blunt by design |
| `voice-script.md` | The first voice script. Superseded by `docs/voice-script-v2.md` when the story changed from the Moon to an unnamed planet |
| `TASK-voice-recording.md` | The brief for recording the voice performance |
| `TASK-github-contribution.md` | A drafted upstream contribution to whisper.unity, not yet filed |
| `demo-video.md` | Shot list for a demo video |
| `itch-page.md` | Draft store page copy |
| `level-design-brief.md` | The brief the six sectors were designed against, written as a set of open questions. Most were answered in `docs/levels.md` |
| `voice-recording-guide.md` | How to record and process the voice performance |
